# 03 — On-chain Ultrahonk verification wiring + replace mock reveal with reveal_move(proof,...)

## Goal
Replace the mock reveal with real ZK verification:
- Deploy or vendor the Ultrahonk verifier contract (`indextree/ultrahonk_soroban_contract` or an adapter)
- Update the rps_game contract:
  - reveal_move(session_id, player, proof, public_inputs)
  - verify proof via cross-contract call
  - validate public commitment matches stored commitment
  - store move from public output
- Keep finalize logic unchanged.

## Constraints
- No backend.
- Public inputs decoding must match exactly what verifier expects.
- Keep commitment representation consistent between:
  - Noir circuit output
  - bb.js output serialization
  - Soroban verifier input format
- Add an adapter contract if needed to normalize formats.

## Tasks
1) Add verifier contract to repo (as submodule or vendored code under `contracts/verifier/`).
2) Identify the verifier function signature and expected types.
3) Define a canonical encoding for `public_inputs` passed from frontend:
   - e.g. Vec<i128> field elements OR Bytes
4) Implement in rps_game:
   - `reveal_move(env, session_id, player, proof: Bytes, public_inputs: Vec<...>)`
   - call verifier -> bool
   - parse `commitment` and `move_public` from public inputs
   - validate commitment == stored commitment for player
   - validate move in 0..2
5) Update tests:
   - Add a mocked verifier contract for unit tests (returns true and echoes inputs) OR
   - If feasible, add an integration test that uses real proof artifacts generated in task 02 (can be a separate e2e script).

## Completion criteria
- rps_game no longer exposes reveal_move_mock
- Unit tests pass
- At least one automated e2e path exists (local or testnet) showing:
  - commit -> reveal(proof) -> finalize works end-to-end
- Clear README notes on how to deploy verifier + game contract
