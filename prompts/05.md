# 05 — Hardening + E2E automation + documentation polish

## Goal
Turn the MVP into a reliable demo:
- Add missing view/getters on contract to reduce frontend complexity
- Add robust e2e scripts (node) to run the whole game automatically
- Improve UX and error messages
- Document deployment and demo steps

## Tasks
1) Soroban contract improvements:
   - Add read functions:
     - get_session(session_id) -> SessionData (or a subset)
     - get_commitment(session_id, player) -> Option<BytesN<32>>
     - get_move(session_id, player) -> Option<u32>
   - Ensure these are pure reads or documented as such.
2) E2E scripts:
   - `scripts/e2e.mjs`:
     - deploy verifier + game contract (if needed)
     - create session
     - commit for p1/p2
     - generate proofs using circuit artifacts
     - reveal
     - finalize
     - assert winner
3) Frontend polish:
   - better status indicators
   - disable actions when not allowed
   - clear deadline/forfeit explanation
4) Docs:
   - Root README.md:
     - prerequisites
     - build steps for circuit/contract/frontend
     - deployment to testnet
     - demo walkthrough
   - Include known issues + troubleshooting section (proof inputs mismatch, field encoding, etc.)

## Completion criteria
- One-command e2e run succeeds consistently (local + testnet if possible)
- README allows a new dev to reproduce the demo
- Frontend blocks invalid actions and surfaces errors clearly
