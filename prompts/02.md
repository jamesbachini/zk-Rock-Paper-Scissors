# 02 — Implement Noir circuit for commitment proof + produce bb.js-ready artifacts

## Goal
Create the Noir circuit described in spec.md and produce artifacts needed for bb.js in the browser:
- private inputs: move, salt (and optionally session_id + player if you implement the safer commitment)
- public outputs: commitment, move_public
- constraints:
  - move in {0,1,2}
  - commitment computed with Poseidon (Barretenberg-compatible)
- build scripts that generate the proving/verifying artifacts required by bb.js and the Soroban verifier

## Constraints
- Use Noir tooling compatible with bb.js / Barretenberg.
- Keep public output ordering EXACT:
  1) commitment
  2) move_public
- Document field encoding / endianness expectations for commitment.

## Tasks
1) Create `circuits/rps_commit/` Noir project.
2) Implement circuit:
   - Choose commitment formula:
     - Recommended: Poseidon(session_id, player_field, move, salt)
     - If player encoding is hard, at minimum include session_id to prevent cross-session replay.
   - Document the exact formula and how frontend computes it.
3) Add scripts (package.json or Makefile) to:
   - compile Noir
   - generate bb.js proving artifacts (ACIR + whatever bb.js requires)
   - generate verification key / data for on-chain verifier integration (as required later)

## Developer docs
Write `circuits/rps_commit/README.md` with:
- input/output schema
- how to run build
- example values + expected commitment output (sanity vector)
- how to map session_id and player address into field elements (if used)

## Completion criteria
- Circuit compiles successfully
- You can run a local proving script (node is fine) that:
  - inputs move+salt(+session_id)
  - outputs proof + public outputs
  - verifies proof off-chain using bb.js APIs (or barretenberg verifier)
- Public outputs order is verified by tests or assertions
