# rps_commit Noir Circuit

A minimal commit-reveal circuit for Rock / Paper / Scissors using Poseidon2 and
Ultrahonk-compatible outputs.

## Inputs / Outputs

Private inputs:
- `move: u8` — 0 = Rock, 1 = Paper, 2 = Scissors
- `salt: Field` — random secret (store locally)
- `session_id: Field` — binds commitment to a session

Public outputs (order is **strict**):
1. `commitment: Field`
2. `move_public: Field`

## Commitment Formula

We use Poseidon2 over BN254 with a 2-input hash, chained to include `session_id`:

```
inner = Poseidon2Hash(session_id, move)
commitment = Poseidon2Hash(inner, salt)
```

This matches the Barretenberg `poseidon2_hash` primitive used by `@aztec/bb.js`.
The circuit enforces `move <= 2` and exposes `[commitment, move_public]` as
public outputs in that exact order.

Example JS (frontend) computation:

```ts
import { BarretenbergSync, Fr } from '@aztec/bb.js';

const api = await BarretenbergSync.new();
const inner = api.poseidon2Hash([new Fr(sessionId), new Fr(move)]);
const commitment = api.poseidon2Hash([inner, new Fr(salt)]).toString();
```

## Field Encoding / Endianness

- All values are BN254 Fr field elements.
- In JS, pass inputs as `BigInt` or decimal strings.
- `@aztec/bb.js` returns field elements as **big-endian** hex strings (`0x…`).
- For Soroban, serialize field elements as 32-byte **big-endian** values.
  - Left-pad with zeros to 32 bytes.

### Mapping `session_id`

`session_id` is a `u32` encoded into a field element. In JS:

```
const sessionIdField = BigInt(sessionIdU32);
```

### Mapping player address (optional future hardening)

If you later include a player address in the commitment:
1. Decode Stellar StrKey to 32 raw public key bytes (ed25519).
2. Interpret as a big-endian integer.
3. Reduce mod the field if necessary (or reject if >= modulus).
4. Use that field element as `player_field`.

## Build & Prove

**Important:** The Soroban verifier uses **Keccak** for the Fiat–Shamir
transcript. Generate proofs (and VK) with `UltraHonkBackend` using
`{ keccak: true }` so on-chain verification matches.

From `circuits/rps_commit`:

```bash
bun install
bun run compile
bun run prove
bun run artifacts
bun run prove:artifacts
```

- `bun run prove`:
  - generates a proof with bb.js
  - verifies it off-chain
  - asserts public output ordering
  - checks commitment against bb.js Poseidon2
- `bun run prove:artifacts`:
  - writes `artifacts/proof.bin` and `artifacts/public_inputs.bin`
  - uses the fixed inputs from this README (move=1, salt=123456789, session_id=424242)
  - intended for on-chain and contract integration tests

Tested with:
- `@aztec/bb.js@0.87.0`
- `@noir-lang/noir_js@1.0.0-beta.9`
- `nargo 1.0.0-beta.9`
